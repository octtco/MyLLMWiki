# 《深入理解 AI Agent》阅读讨论（2026-09-22 ~ 09-24）

维护者正在精读 [bojieli/ai-agent-book](https://github.com/bojieli/ai-agent-book)（2.0 版中文正文），本页保存讨论期的概念问答与纠偏记录。讨论期约定：先解释、后入库；本页即"讨论整理入库"的第一步，全书来源包与来源页另行补建。续篇见 [[2026-09-29 问答 - 消融实验与服务端编排路径]]。

## 短答案（每问一行）

1. **DOM**：浏览器把 HTML 解析成的树形对象结构；Web Agent 优先读它定位可交互元素，读不到（Canvas/WebGL/游戏）才退回截图视觉路线。
2. **无障碍树**：从 DOM 蒸馏出的语义子集，节点 = Role/Name/Value + 关系字段；比 DOM 更小、自带语义、跨应用统一。
3. **元素是否进无障碍树**：裁剪依据是"对非视觉用户有没有信息量"（语义），不是"有没有交互属性"；逐节点独立判断，父子互不牵连，渲染层（display:none 等）一票否决。
4. **语义来源五层**：标签隐式角色 → 有无障碍映射的属性（alt/label/checked…）→ 文本与结构关系 → 渲染状态否决 → ARIA 补丁（最后手段）。
5. **强化学习**：试错 + 奖励信号学策略；只给分数不给答案，靠梯度把参数往"奖励变大"的方向拨。
6. **三范式区分**：监督（人给答案）/ 无监督（数据自身结构）/ 强化（环境给分数）；GPT 预训练是自监督——答案藏在文本自身（猜下一个词），处在光谱中间。
7. **无监督怎么知道方向**：目标不用人给但仍可计算——聚类看离群中心距离、PCA 看还原误差、自监督看与原文的差异；有可算的 loss 就有梯度，机制与监督学习相同。
8. **机器学习不神秘**：模型 = 参数化的算术式；学习 = "猜 → 打分 → 微调"循环（梯度下降）几十万次；知识就存在参数数值里。
9. **工具设计原则 vs Pi 极简**：书的默认取向本就是"通用工具优先，四种例外才特化"（`chapter4.md:49`）；Pi 是默认情形的极致实现，其专用工具下沉到 bash 层的 CLI，约束从 schema 移到权限层，不是矛盾而是适用前提不同（强模型 + 人在场 + CLI 生态成熟）。
10. **schema**：工具参数的 JSON 格式说明书（name/description/parameters）；完整 schema 可按需追加到上下文末尾以省 token 且不破坏静态前缀缓存。
11. **"非盲目随机探索"**（`chapter1.md:113`）：传统 RL 靠掷骰子试错撞出策略；LLM Agent 先用预训练知识在脑内推演再行动——"先知后试"对比"先试后知"。

## 展开（讨论中的关键纠偏）

### DOM 与无障碍树

- 书中 DOM 语境集中在 Computer Use / Web Agent（第 1、6、7 章）：结构化可得时优先 DOM/A11y 索引（`chapter6.md:540`），browser-use 路线经 CDP 取树 → 枚举编号 → 模型选 ID，把坐标预测这道"填空题"变成"选择题"（`chapter6.md:508`）。
- 维护者最初的两个误解已纠正：
  1. "无交互属性 + 无交互子元素 → 被裁" → 修正为"无语义贡献才被裁"；静态文本、标题、地标都保留且占大头；包裹层与子节点各自独立判定，子节点会 re-parent。
  2. 误以为存在"没反馈的箭头"（RL 环路图）→ 是作图冗余，反馈只有"状态 + 奖励"一条回路。
- 无障碍树节点结构：Role（button/textbox/heading…）+ Name（label/alt/placeholder 映射）+ Value/State + 关系字段；Web 经 CDP `Accessibility.getFullAXTree`，桌面经 OS 级 API（UI Automation / NSAccessibility / AT-SPI）；ARIA 是第五层补丁，也能反向抹除语义（role="presentation"、aria-hidden）。
- 实践自检方法：Chrome DevTools → Accessibility 面板直接看浏览器算出的 Role/Name/Value 及 ignored 原因。

### 机器学习三范式与"神奇感"

- 传统 RL 盲目探索 vs LLM 结构化知识探索的对照：婴儿乱按按钮 vs 读过说明书的工程师；样本效率差几十万倍（书中 Q 表实验前 5000 局胜率 0，`chapter8.md:196`）。
- 诚实边界已注明：LLM 运行时仍有采样探索（非零）；训练 LLM 的后训练仍需大量 rollout 试错，书中那句说的是**推理阶段**行为方式。
- 涌现与可解释性是开放问题，书中第 8 章才是训练机制主战场；前七章把 LLM 当组件用，当前理解深度足够。

### 工具设计：书的原则与 Pi 的极简

- 谱系两端：专用工具（schema 约束、可测试、每条数百 token）vs Skill + 通用执行器（目录条目数十 token、用到才读），见 `chapter4.md:40-47`。
- 四种退回专用工具的情形（`chapter4.md:53`）：安全权限审计、屏蔽平台差异、使用频率极高、参数结构复杂。
- Pi（earendil-works/pi）立场：核心不内置 MCP，能力封装为带 README 的 CLI + Skills 按需加载；社区 `pi-mcp-adapter` 用约 200 token 代理工具实现渐进披露（`chapter4.md:143`）。"形态"与"披露数量"是两个独立决策（`chapter4.md:47`）。
- 关键调和：Pi 的极简前提 = 强模型 + 用户在场监督 + 开发者 CLI 生态成熟（`chapter4.md:64` 的"模型能力"维度）；生产系统的高风险、强业务规则场景应按书的原则退回专用工具。约束没有消失，只是从工具 schema 移到了 harness 权限层。
- 注意："Pi 工具只有一个 bash"是维护者记忆，书中未见此精确表述（书只记载"No MCP"哲学，`chapter4.md:145`），待核实。

### 消融与工具定义

- 工具定义 = 名称 + 描述 + 参数 schema 的 JSON；不给定义模型无从调用，但拿掉定义 Agent 不会停机而是行为退化（实验 1-1 消融的设计意图）——工具定义是引导物不是开关。
- 静态前缀（系统提示词 + 工具定义）命中 Prompt Cache（约 1/10 成本）；2026 年以来完整 schema 可动态追加到末尾而不破坏前缀（`chapter2.md:700`、`chapter4.md:177`）。
