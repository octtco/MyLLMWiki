# 《深入理解 AI Agent》阅读讨论·二（2026-09-28 ~ 09-29）

本批聚焦第 1 章后半：上下文组件消融、ReAct 最小骨架、模型即 Agent 的两条接入路径，以及由此延伸到"开发 Agent 如何选编排位置"的工程判断。

## 短答案（每问一行）

1. **消融实验**：控制变量法的工程版——逐个拆掉组件测退化量，用数字证明"谁真的必要"；实验 1-1 = 1 个全量基线 + 4 个各缺一件（系统提示词不参与，缺了无角色认知）。
2. **消融结论**：工具定义是行动能力的命（缺失→不停机而是编造格式工整的假答案）；工具执行结果是闭环的命（缺失→盲目重试耗尽预算）；思考过程可从工具结果重建时丢弃几无代价；历史消息防重复犯错。
3. **"思考可从结果重建"的例子**：读 requirements.txt → 结果里没有缺失模块 → 接着 pip install——动作+结果序列已蕴含意图；反例是"用户约定过不能装包"这类只存在于思考里的约束，丢了就丢信息。判断标准：**只看动作与结果序列能否唯一推出当时理由**。
4. **`Harness.validate(call)`**：执行前安检口——schema 格式、权限风险（如 `rm -rf` 拒绝/转人工确认）、防提示注入（只看结构化字段不看话术）、保真性（不静默篡改参数）。核心立场：模型输出是不可信输入，真实世界变化必须框架层独立校验。
5. **Formula**：Kimi 的服务端脚本引擎，`web_search`/`code_runner` 的真实实现在云端——用 API 不需本地实现这些工具；但"工具在云端"≠"循环在云端"。
6. **"编排循环没有消失"**：编排 = 决策（下一步干什么）+ 机械迭代（调用-执行-回填-再调用的转圈代码）。决策进模型参数；迭代必须有人转。两种常见误解：把决策搬家当整个循环搬家；把"客户端无需搭编排框架"读成编排消失。
7. **两条路径对比**：1-2 Kimi = 决策云端 / 循环本地 / 工具执行云端 Formula（本地发起、云端执行）；1-3 GPT Responses = 三者全云端。同厂商可同时提供两条路径，区别在路径不在厂商。
8. **服务端循环的收益**：省网络往返与上下文跨网传输（100 步变 1 次连接）只是表层；更重的是客户端零编排、断线不失联、闭环错误由厂商兜底、服务端可做内部优化。
9. **"等价托管工具"不矛盾**：那句话对齐的是"工具执行"列（Formula/qwen 内置工具都有），不蕴含"服务端循环"列等价；协议兼容（Responses 格式）是义务，托管工具是选配。
10. **开源部署卖算力的三层**：卖 token（无护城河）→ 卖开箱即用的工具调用 API（需模型侧 RL 后训练，部署补不上）→ 卖端到端托管 Agent 步骤（Formula 类基建 + 服务端编排）。只部署不配套 = 最没溢价的层。
11. **开发 Agent 要不要考虑服务端循环**：要，但第二顺位；第一顺位是"工具作用于谁的状态"——动自己的文件/内部系统则循环必须在本地，纯托管工具任务才值得考虑服务端循环；混合是常态（主循环本地，研究子任务整包外包）。本地循环的隐性优势：模型中立性（防锁定）+ 完整轨迹可观测（第七章评估的数据来源）。

## 展开（本批讨论的关键推理链）

### 消融与上下文组件

- 方法来源：医学"切除组织观察功能缺损"思想；ML 论文常见形态是 `w/o X` 对照表，审稿人用它验证模块贡献。
- 局限已记录：单变量消融测不到组件交互；结论绑定当前模型（`chapter1.md:159` 明示）；"没掉点"不等于没用。
- 工程要点：上下文残缺时的典型失败**不是报错而是无破绽的假答案**——这解释了"工具定义是引导物不是开关"。

### 编排的两半

- 服务端循环适用边界：工具操作厂商云端状态（搜索、厂商沙盒代码）→ 可行；操作本地文件/内部系统 → 圈转不起来。补充：部分 Responses 实现允许服务端循环回调自有 HTTP 函数工具，但本地文件类仍须本地执行。
- 决策表（本地 vs 服务端循环）按六维展开：工具拓扑、任务形态、可观测性、断线可靠性、上下文体量、模型中立性。
- 开发建议：操作自己状态的 agent 默认本地循环 + function calling；联网研究类子任务可整包外包给服务端循环，主循环留本地——**混合是常态**。

### 商业延伸（部署卖算力）

- 硬门槛在第二层：工具调用决策能力是 RL 后训练写进参数的，不是部署出来的（呼应 Issue #30 区分：RL 内化决策，不内化执行）。
- 生意分层：卖算力 < 卖工具调用 API < 卖 Agent 平台；与第一章"Harness 才是竞争力"论点同构。
